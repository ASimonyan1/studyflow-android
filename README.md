# StudyFlow · Android

[![Android CI](https://github.com/ASimonyan1/studyflow-android/actions/workflows/android.yml/badge.svg)](https://github.com/ASimonyan1/studyflow-android/actions/workflows/android.yml)

**Меньше хаоса. Больше сделанного.**

Небольшой Android-планировщик учебных задач. Предметы, сроки и прогресс в одном месте; данные хранятся на устройстве, регистрация и интернет не нужны.

## Возможности

- Создание и редактирование задачи: название, предмет, необязательный срок.
- Выполнение и возвращение задачи в работу, удаление с подтверждением.
- Поиск по названию и предмету, фильтры «В работе», «Все», «Готово».
- Сортировка: сначала активные задачи с ближайшим сроком, затем без срока, затем выполненные.
- Просроченные задачи выделяются; задача со сроком сегодня ещё не просрочена.
- Локальная база Room, светлая и тёмная темы, состояния загрузки и ошибок.
- Черновик редактора, поиск и выбранный фильтр переживают поворот экрана.

## Технологии

Kotlin · Jetpack Compose · Material 3 · Room / SQLite · Coroutines / Flow · ViewModel · JUnit · GitHub Actions.

## Запуск

1. Клонируйте репозиторий и откройте его корень в Android Studio.
2. Выберите JDK 17 или 21 для Gradle; установите Android SDK 35 через SDK Manager.
3. Дождитесь Gradle Sync и запустите `app` на устройстве/эмуляторе Android 8.0+ (API 26+).

```bash
./gradlew testDebugUnitTest lintDebug assembleDebug
```

В Windows используйте `gradlew.bat`. SDK определяется через `local.properties` (не коммитится) или `ANDROID_HOME`.

Debug APK: `app/build/outputs/apk/debug/app-debug.apk`. После успешного CI он также доступен в разделе **Actions → Android CI → выбранный запуск → Artifacts → studyflow-debug-apk**. Для скачивания артефакта GitHub может потребоваться вход.

## Как устроен проект

```text
app/src/main/java/dev/asimonyan/studyflow/
├── MainActivity.kt          — точка входа и создание зависимостей
├── data/
│   ├── Task.kt              — модель и чистые правила фильтрации/сортировки
│   └── TaskDatabase.kt      — Room DAO, база и репозиторий
└── ui/
    ├── TaskViewModel.kt     — состояние и операции с задачами
    └── StudyFlowScreen.kt   — Compose UI и редактор
```

Данные идут по цепочке **Room → Flow → ViewModel → Compose**; пользовательские действия проходят обратно через репозиторий. База — единственный источник списка задач. Переключение статуса выполняется атомарным SQL-запросом, чтобы быстрые нажатия не зависели от устаревшего снимка UI.

Дата хранится как `LocalDate.toEpochDay()`: дедлайн — календарный день, а не момент времени в UTC. Поэтому смена часового пояса не сдвигает выбранную дату. Текущее число обновляется при возвращении в приложение и раз в минуту.

Для небольшого прототипа используется ручное внедрение зависимостей: интерфейс `TaskRepository` позволяет подменять хранилище в тестах без DI-фреймворка. Поиск выполняется в памяти; для большой базы следующим шагом будет SQL/FTS-поиск.

## Проверки

CI запускает сборку debug APK, Android Lint и JVM-тесты правил: границы дедлайна, фильтрацию, поиск, сортировку и валидацию названия.

Инструментальный тест `TaskDatabaseTest` проверяет полный цикл создания, изменения, переключения статуса и удаления через настоящую Room-базу. Для него нужен запущенный эмулятор или устройство:

```bash
./gradlew connectedDebugAndroidTest
```

Отдельный workflow **Device tests and screenshots** запускает тесты на эмуляторе Android 10 (API 29). UI-тест проверяет создание задачи, поиск и перенос в «Готово»; тест базы проверяет операции Room. [Успешный запуск](https://github.com/ASimonyan1/studyflow-android/actions/runs/36068146859).

Пошаговая ручная проверка: [docs/TESTING.md](docs/TESTING.md).

## Границы версии

Это учебный прототип, подготовленный с помощью AI-инструментов. Нет серверной синхронизации, уведомлений, учётных записей и публикации в Google Play. Удаление приложения удаляет задачи; резервное копирование отключено. Проверка на эмуляторе не заменяет тестирование на физических устройствах и других версиях Android.

План развития: расширение UI-тестов, экспорт задач, напоминания и миграции схемы при добавлении новых полей. Синхронизация — отдельная будущая задача с явным разрешением конфликтов.
